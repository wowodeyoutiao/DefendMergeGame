# 关卡差异化设计（GDD 章节）

> 版本：v1（原型阶段） ｜ 适用项目：合战守格 ｜ 关联系统：三武将攻击轴（sword=同列 / fan=同行 / rock=半径）、波次刷怪、肉鸽卡牌三选一、棋盘
> 目标：解决「每关之间无差异化、无策略性」问题，让玩家**看见**并**应对**每一关的不同。

---

## 1. 问题陈述

现状（已核对代码）：
- 怪物只有 4 个「数值桶」（`normal / runner / brute / elite`），区别仅是 `move / hp / reward`；
- 章节（`CHAPTERS`）仅换皮 + 换 roster 顺序，**无机制差异**；
- 棋盘恒定；胜负永远是「撑过波次」；`lanePattern` 按 `round%3` 死循环；
- 肉鸽卡牌（`CARD_DEFINITIONS`，6 张）全是**通用全局增益**，且随机抽 3 张，与关卡威胁**完全脱钩**。

结论：差异 = 纯数值缩放 → 玩家每关都在干同一件事，策略感知为零。卡牌也因「无上下文、无代价、无协同」而缺乏乐趣。

---

## 2. 设计支柱

差异化的感知必须靠**三层信号**叠加，单靠一层都不够：

| 层 | 作用 | 实现成本 | 优先级 |
|---|---|---|---|
| ① 关卡预告（出战前显式提示） | 策略主入口：直接告诉玩家「这关该投资谁 / 怎么摆」 | 低（文字 + 读数据） | **最高** |
| ② 战斗中特性徽章（always-on 视觉） | 棋盘上扫一眼即知这波怪克谁 | 低（CSS 文本徽章，零美术） | 高 |
| ③ 首遇教学 tip | 某特性第一次出现时飘一行说明 | 中 | 中（原型可后置） |

> **不依赖「怪物外形重做」做唯一信号**：美术成本高、玩家需重学视觉语言。徽章 + 预告已能把意图讲清，外形为锦上添花。

棋盘修正同理：开局一条**状态横幅** + 受影响格子 **CSS 染色**，玩家立刻读懂本关布局约束。

## 3. 怪物特性标签体系（MONSTER_TRAITS）

特性标签直接贴「三武将攻击轴」，制造「本关该养谁」的抉择。

| trait | 徽章 | 配色 | 机制表现 | 克制武将 | 设计意图 |
|---|---|---|---|---|---|
| `columnArmor` 列甲 | 列 | 蓝 #3aa0ff | 仅被**同列**武将（男法师）全额伤害，其余攻击 **−60%** | sword | 逼本关堆法师 |
| `rowArmor` 行甲 | 行 | 橙 #ff7a45 | 仅被**同行**武将（男战士）全额伤害，其余攻击 **−60%** | fan | 逼本关堆战士 |
| `swarm` 群涌 | 群 | 紫 #9b59ff | 血 ×0.6、移动 ×1.25、数量偏多 | rock（范围） | 范围清场吃香 |
| `giant` 巨躯 | 巨 | 红 #d4503a | 血 ×1.6、移动 ×0.7（单体超高血慢速） | sword（列爆发） | 单点突破 |
| `evasion` 闪避 | 闪 | 灰 #8a8f99 | `dodge` +0.35，薄行带易打空 | rock / 精准卡 | 逼合成升档或范围 |
| `ironwall` 铁壁 | 壁 | 钢灰 #6b7280 | `resilience` +0.4，需高 tier / 破甲卡 | （无单一，靠养成） | 逼合成升档 |

**数值落地位置**（原型已接入）：
- 减伤：`attackMonsters` 计算 `finalDamage` 时，按 `monster.trait` 与 `piece.type` 轴比对，非克制武将 ×(1−0.6)；
- `evasion` / `ironwall`：在 `spawnMonster` 给怪物叠加 `dodge / resilience`，复用现有 `resolveWarriorAttack` 命中/暴击公式；
- `swarm` / `giant`：`spawnMonster` 按系数调 `hp / moveSpeed`。

## 4. 棋盘修正层（BOARD_MODIFIERS）

| modifier | 表现 | 实现（原型） | 风险 |
|---|---|---|---|
| `blessedColumn` 增益列 | 某列武将攻击距离 +1 | `attackMonsters` 中 `unit.c === blessedColumn` 时 `attackRange +1`；该列 CSS 金色染色 | 低 |
| `hazardColumn` 险恶列 | 该列怪物移动 ×1.3 | `spawnMonster` 中 `c === hazardColumn` 时 `moveSpeed ×1.3`；该列 CSS 红色染色 | 低 |
| `lockCells` 锁格 | 部分格不可放/不可合 | （设计预留，原型未接：需改拖放/合成判定） | 高 |
| `gravityFlip` 重力翻转 | 从顶部递补、行列语义反转 | （设计预留，原型未接：需改递补方向） | 高 |
| `corrosion` 腐蚀格 | 放置后随时间掉 tier | （设计预留，原型未接：需改放置计时） | 高 |

> 原型只接 `blessedColumn` + `hazardColumn` 两个低风险功能项，足以演示「棋盘即策略面」。锁格/翻转/腐蚀为后续版本。

## 5. 关卡预告 + 特性徽章规范

**① 关卡预告（显式策略提示）**
进波前（出战 `showBattle` 后）弹一次 `showModal`：
```
标题：关卡预告 · 冰雪荒原 第 3 关
正文：本关特性【列甲】—— 男法师（同列）输出最佳；本关含【增益列】。
      推荐：重点培养男法师，把法师放在增益列上。
```
仅在 `state.level` 变更且非续关时弹一次（`briefingShownForLevel` 防重）。

**② 特性徽章（always-on）**
`renderMonsters` 给带 `trait` 的怪物容器追加 `.monster-trait` 徽章（徽章字 + 配色背景，见 §3 配色）。无需任何美术资源。

**③ 首遇教学 tip（原型后置）**
某 `trait` 首次出现时飘一行说明；原型由「关卡预告」承担教学，徽章承担常驻识别。

**④ 棋盘修正横幅**
开局显示 `本关：增益列（金）/ 险恶列（红）`，对应列 CSS 染色常驻。

## 6. 肉鸽卡牌重做方案（ROGUE CARD 2.0）

**根因**：现有 6 张全是通用全局增益、随机抽 3 张、无代价=无抉择 → 没乐趣。

**方案：trait-aware 加权投放 + 流派专精代价**

**(a) 卡池按本关 `LEVEL_MODIFIERS.cardBias` 加权抽 3 张**
列甲关多给「列系 / 破甲」卡；群涌关多给「范围 / 控场」卡 → 三选一变成「面对这波威胁，你要哪种 counter-build」。

**(b) 新增「专精代价」卡，制造真抉择**（已接入原型）：
| 卡 id | 标题 | 效果（带代价） |
|---|---|---|
| `columnMaster` 列阵精通 | 男法师伤害 **+30%**，男战士 **−15%** |
| `rowMaster` 横扫精通 | 男战士伤害 **+30%**，男法师 **−15%** |
| `areaMaster` 范围精通 | 女祭司伤害 **+30%**，其余 **−10%** |

选了即 commit 一个武将 → 这才是策略。代价在 `applyCard` 写入 `state.warriorDamageMult[type]`，`attackMonsters` 的 `dps` 乘以对应系数。

**(c) 保留原通用卡的「无代价」定位**，但降低其在 targeted 关的权重，避免冲淡抉择。

## 7. 统一数据层：LEVEL_MODIFIERS

所有差异化收进一张数据表，刷怪 / 棋盘 / 卡牌都从它读——差异化用**数据设计**而非改代码。

```js
const LEVEL_MODIFIERS = {
  1: null, 2: null,                                  // 暖场关，无特性
  3: { monsterTrait: "columnArmor", board: null,
       cardBias: { columnMaster: 3, warCry: 2, crossfire: 2 } },
  4: { monsterTrait: "rowArmor", board: null,
       cardBias: { rowMaster: 3, warCry: 2 } },
  5: { monsterTrait: "swarm", board: { hazardColumn: 2 },
       cardBias: { areaMaster: 3, frost: 3, thunder: 2 } },
  6: { monsterTrait: "giant", board: { blessedColumn: 3 },
       cardBias: { columnMaster: 3, execution: 2, thunder: 2 } },
  7: { monsterTrait: "evasion", board: null,
       cardBias: { areaMaster: 2, rapidFire: 2, crossfire: 1 } },
  8: { monsterTrait: "ironwall", board: null,
       cardBias: { warCry: 2, execution: 3, columnMaster: 1 } },
};
```

**样例 10 关递进（设计稿，原型实现 1–8）**

| 关 | 特性 | 棋盘 | 策略焦点 |
|---|---|---|---|
| 1 | — | — | 教学：合成+守城 |
| 2 | — | — | 教学：三武将切换 |
| 3 | 列甲 | — | 养法师 |
| 4 | 行甲 | — | 养战士 |
| 5 | 群涌 | 险恶列 | 范围清场 + 规避险列 |
| 6 | 巨躯 | 增益列 | 法师单点 + 占增益列 |
| 7 | 闪避 | — | 升档 / 范围 |
| 8 | 铁壁 | — | 升档 + 破甲卡 |
| 9 | 列甲+群涌 | 增益列 | 复合：法师占增益列清群 |
| 10 | 行甲+铁壁 | 险恶列 | 复合：战士破甲 + 避险列 |

> 复合关（9/10）证明特性 × 棋盘可组合，是数据层的最大价值。

## 8. 落地顺序与验证

1. **关卡预告 + 特性徽章**（已原型）：轻量、纯 CSS+文字，立刻让「每关不一样」被看见、被策略化；
2. **怪物特性接入伤害结算**（已原型）：§3 六个标签；
3. **棋盘修正 blessedColumn / hazardColumn**（已原型）；
4. **肉鸽卡牌加权投放 + 专精代价**（已原型）；
5. （后续）锁格 / 重力翻转 / 腐蚀格、首遇教学 tip、复合关全量。

**验证**：回归三件套（语法 / 静态扫描 / 90 项 DOM 交互）；真机走 3→8 关，确认每关预告不同、徽章不同、卡牌池不同、克制关系成立（非克制武将伤害 −60% 肉眼可见）。

## 9. 风险与权衡

- **难度曲线**：特性减伤 −60% 较强，需配合 `LEVEL_SCALING` 复核，避免某关不可解；原型以「预告+推荐武将」引导，玩家可按提示通关。
- **Boss 是否带特性**：原型 Boss 不带 trait（保持 Boss 作为「数值天花板」定位），避免双重压力；后续可让 Boss 携带 1 个 trait。
- **存档兼容**：新增 `state.levelModifier / warriorDamageMult / seenTraits` 均为运行时字段，`loadProgress` 清洗时按现有 `isPlainObject` 规则兜底，旧存档不崩。
