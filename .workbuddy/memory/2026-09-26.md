## 战斗棋盘两处规则调整（超哥提出）

- 规则 1 换位方向：改写 `areAdjacentCells`（app.js:2655）为显式"同行列差 1 或 同列行差 1"，斜向一律返回 false；`tryMove` 被拒时新增提示"只能与上下左右相邻的棋子交换，斜向换位不生效，也不消耗步数"。注意：原实现用曼哈顿距离 `=== 1`，语义上其实已排除斜向，只是判定不直观且无反馈。
- 规则 2 递补方向（**重要，超哥纠正过一次**）：原 `refillBoardFromBottom` 是**原地生成新棋子**再播一个从底部飞入的动画，下方元素不上移。正确方向是**从下向上递补**——每列自上而下收集幸存棋子、自上而下写回（列内相对顺序不变），下方棋子逐格上顶，缺口留在**列底部**，由棋盘底部生成新棋子补入。不是重力下沉，上方棋子必须原地不动。上顶棋子打 `rising` + `riseDistance`（= 原行 − 新行，正值），`renderBoard` 设 `--rise-distance`，`styles.css` 用 `@keyframes riseToVacancy`（300ms，从 translateY(正) 归零 = 自下往上滑）。第一版误做成下沉（`falling`/`fallDistance`/`fallToVacancy`），已被推翻，不要沿用。
- 连锁安全阀：递补后棋子移动更容易触发新连线，给 `resolveBoardAfterMove` 加了 `MAX_AUTO_CHAIN = 15` 上限，防止极端随机局面卡死操作期。
- 标记清理：`finishBoardSupplyAnimations` 与 750ms 定时器都会清 `entering/rising/riseDistance`；`createShuffledBoard` 开头也清一次，避免洗牌误播上顶动画。
- 验证方式（可复用）：`tmp/verify-board-rules.mjs` 从 app.js 源码文本里抽取 `refillBoardFromBottom` / `areAdjacentCells`（按行匹配 `}` 结束，注意文件是 CRLF），用 `new Function` 注入 BOARD_SIZE/WARRIORS/newPiece/state 后纯数据断言，共 30 项全通过（含"空位上方棋子原地不动""下方棋子上顶 1 行""整列清空由新棋子补入"等方向性断言）。配合 `node --check app.js` 语法校验。
- 环境坑：本机 curl 走代理，访问 127.0.0.1 会返回 502，需加 `--noproxy '*'`；`node tools/serve.mjs --port 5173` 已在后台运行可直接试玩。
