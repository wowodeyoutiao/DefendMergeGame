# 2026-10-09 工作日志

## Bug 修复：通关后点「下一关」，广告提示/洗牌按钮不可点
- **根因**：`canRequestMergeHint` / `canRequestBoardShuffle` 的启用条件里带了 `state.levelStaminaSpent`。两条进关路径置位时机不一致——
  - 从主页进关（`startLevelFromHome`）：进关即扣体力并置 `levelStaminaSpent = true` → 按钮可用；
  - 通关后点「下一关」（`nextLevel` → `resetGame`）：只把标记清成 false，体力要等第一次「出怪」（`startWave`）才结算 → 新关开局操作期两按钮被锁死，且出怪后进入 combat 又不可用，要等第一波打完才恢复。
- **修复（3 处）**：
  1. 两个 `canRequest*` 去掉 `levelStaminaSpent` 依赖（该标记语义是"本关体力已扣/是否有未结束战局"，不该用来卡操作期辅助功能），只保留 battle + setup + 非结算 + 次数未用尽。
  2. `resetGame` 补 `state.adPlayback = null`，清残留广告态（否则换关/重开后仍可能被旧状态锁死）。
  3. 新增 `restartLevel()`（重开保留已付体力标记），替换 `resetBtn` 与两处「重开本关」入口的 `resetGame` —— 顺带修掉**重开会被重复扣一次体力**的经济 bug（resetGame 清标记 → 出怪再扣 10）。
- **验证**：新增 `tools/verify/verify-next-level-ad-buttons.mjs`（jsdom 真跑「下一关」与「重开」两条路径，15 项全过）；`node --check` / static-scan / regression-dom 90 项全过；服务探活 200。
- 状态：**未 git commit**（超哥靠 IDE 变更列表核对）。改动文件 `app.js` + 新增 `tools/verify/verify-next-level-ad-buttons.mjs`。
