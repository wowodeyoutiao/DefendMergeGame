### 修掉的 3 个真问题

1. **装备 id 复用（严重）**：`loadProgress` 只做 `Number.isSafeInteger` 判断，老存档缺 `equipmentNextId` 时回落到 1，而包裹里可能已有 id 1~3 → 新装备复用 id → `equipmentInventory.find(item => item.id === id)` 命中错的那件，**按 id 穿戴/出售会操作到别的装备**。现在按"已用 id 集合 + 最大值"去重，nextId 保证严格大于所有已用 id（包裹与已穿戴装备一起算）。
2. **脏存档导致包裹永久损坏（严重）**：`equipmentInventory` 只判 `Array.isArray`，条目本身不校验。存档里出现 `null` / 非对象 / 部位非法时，包裹渲染直接抛 `Cannot read properties of null (reading 'quality')`；更糟的是脏数据会被原样写回存档，**玩家自己永远恢复不了**。新增 `sanitizeEquipmentItem` 逐项清洗（无法修复的丢弃、缺失字段按部位+品质回落默认值、武器/衣服保留合法职业），并顺带清洗 `warriorEquipment` / `warriorQuality` / `warriorPermanentStats`（原来用展开运算符合并，存档里是字符串时会把数字键混进对象，NaN 会顺着伤害公式扩散）。
   - 注意：武将品质上界用的是**品质档数（7）而不是 MAX_WARRIOR_QUALITY（6）**，为的是不倒扣旧存档里已有的金色，符合"属性不降级"的既有约定。
3. **商店兑换的空值保护**：兑换成功后更新 `modalDetail` 里的三个节点，未做空值判断。正常玩法点不到（点广告卡后商店面板已被替换），但既然封版就加了保护，避免任何"面板被换掉后处理器仍存活"的路径抛错。
