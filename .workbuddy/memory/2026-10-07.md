## 胜利结算界面只显示脚本文字、无图标（bug 修复，8d75292）
- 超哥反馈：胜利结算界面全是脚本文字，没有图标展示。
- 根因：`showVictory` 把整段 HTML（rewardsHtml + 文案）传给 `showModal`，但 `showModal`（app.js:4300）用 `modalBody.textContent = body` 渲染，HTML 被当纯文本原样显示 → 用户看到 `<div class="victory-reward">…<img>…` 这类源码，图标不解析。
- 既定型模式：项目中 `showLevelBriefing`（2766）、武将界面顶栏（4773）都在 `showModal` 之后用 `modalBody.innerHTML =` 覆盖 body 区；`showVictory` 漏了这一行。
- 修复：在 `showModal("胜利结算", body, victoryActions);` 之后加 `modalBody.innerHTML = body;`（app.js:4723 附近）。CSS（theme.css:2652-2690 `.reward-frame`/`.victory-reward`/`.vf-1~8`）本来齐全，无需改样式。
- 验证：node --check ✅ / static-scan ✅ / regression-dom 90 项 ✅；服务 5173 = 200。
- 提交：`8d75292`（仅 app.js，+1/−0）。

### 经验（防再犯）
- 任何把 HTML 字符串传给 `showModal` 的调用点，必须在 `showModal` 之后用 `modalBody.innerHTML = body` 覆盖，否则 HTML 被 `textContent` 当源码显示。建议后续把该覆盖逻辑直接内化进 `showModal`（加一个 `options.html=true` 选项）以根除此类遗漏。

### 关键发现
- 关卡是**无限程序化**的：`getChapterIndex(level)=floor((level-1)/5)`，7 个章节循环；原 `LEVEL_MODIFIERS` 只定义 1-8，9+ 返回 `null`（无特性）→ 高关退化成"无差异化关"。所以"所有关卡"必须做成循环覆盖。
- 挑战模式复用同一 `state.level`（`isChallengeMode()` 分支），由 `CHALLENGE_MODE_CONFIG` 接管波数/Boss/怪量/奖励等数值难度。

### 改动
- **特性数组化**：`monster.trait`（单）改为 `monster.traits`（数组）。改 4 处：`spawnMonster`（叠加多特性 hp/move/dodge/resilience）、`traitDamageMultiplier`（遍历数组连乘减伤）、`renderMonsters`（多徽章，按索引右移避免重叠，用 `dataset.traitKey` 防每帧重建）、`showLevelBriefing`/选关预览（多徽章 + 多描述 + 多推荐武将）。

- **挑战关更丰富**：`enrichChallenge(base,level)` = 普通关叠加**第二特性** + 补齐**双棋盘修正**（险恶列2 + 增益列3）。规则：第二特性**不与主特性同为减伤轴**（col/row 不配对），保证至少一名武将满伤可解（避免无解）；卡牌池合并双特性 bias + `challenge:1`。
- 统一出口 `getStageModifier(level)` 按 `isChallengeMode()` 分流；`showLevelBriefing` 与选关预览都改走它（挑战关选关界面即显示更丰富条件）。
- 校验脚本独立跑了 1-60 关不变量：每关有特性、挑战关恒为 2 特性、无"减伤轴+减伤轴"组合、双棋盘修正恒在 → INVARIANTS OK。
